# UI-04 我的活動

本分支實作 UI-04、US-04／US-05 中的報名紀錄與取消流程。不包含 UI-03 登入、重新報名、出席登記或管理者功能。

## 本機啟動

1. 在 `server` 執行 `npm ci`。
2. 複製 `.env.example` 為 `.env`，填入自己的 PostgreSQL 連線設定。
3. 設定 `NODE_ENV=development`、`UI04_LOCAL_TEST=true`，並將 `UI04_TEST_USER_ID` 設成既有的 `users.id`。
4. 執行 `node --env-file=.env index.js`。
5. 開啟 http://127.0.0.1:8000/my-activities.html 。需從此伺服器開啟，不能直接用 file:// 開啟。

頁面標示測試帳號，取消操作會修改真實資料庫紀錄。使用專用測試帳號及測試資料；不會自動建立或刪除資料。更換帳號需修改後端設定並重啟服務，前端不能指定帳號。勿將此模式用在共享或公開環境，也勿透過代理轉發。伺服器只綁定 loopback；正式環境若誤啟測試模式會拒絕啟動。

未啟用測試模式時 API 回傳 401。UI-03 完成後，將 `localIdentity` 換成真正的登入驗證中介層，從驗證過的 session 設定 `req.currentUserId`，並移除測試模式 metadata；不能改成讀取前端 user_id。

## API

- `GET /api/users/me/registrations`：本人全部 registered／cancelled 紀錄，依 registered_at DESC、id DESC 排序；空資料回傳 `{data:[]}`。回傳格式沿用 registration-service，另有本機測試 meta。
- `POST /api/users/me/registrations/:id/cancel`：JSON body `{}`，需 `X-UI04-Request: 1`。同源操作；成功回傳 `{data:{id,status:"cancelled"}}`。
- 401：沒有可用身分；400：編號格式錯誤；403：不允許的請求來源；404：不存在或不是本人紀錄；409：活動已開始；500：資料庫失敗（不暴露內部資訊）。

取消交易鎖定報名與活動資料，在資料庫以目前時間確認尚未開始，只更新 status、不刪除紀錄。已取消紀錄再次請求回傳相同成功結果；不修改名額（目前 schema 沒有名額欄位）。不允許取消他人紀錄。未接上出席資料前，不推定實際參與，畫面顯示「尚未開放」。

## 驗證

執行 `node --test ui04.test.js` 驗證 API 身分來源、未登入、來源保護、錯誤回應與輸入驗證。這些使用替身 service，不代表真實資料庫已驗證。

資料庫整合驗收（使用可修改的測試資料）：

- 兩個帳號分別查詢，確認不能查到另一人的紀錄；竄改取消 id 會回傳 404。
- 未開始的已報名活動取消前選擇「保留報名」不修改資料；確認後重新整理仍為已取消。
- 重複及同時取消只有一次狀態轉換，原紀錄仍保留。
- 活動已開始不能取消；活動結束仍只顯示報名狀態，不列為已參與。
- 關閉資料庫時顯示錯誤與重試，不誤顯示空清單或取消成功。
- 無報名、只有取消、同活動多筆歷程、手機版與鍵盤操作皆需檢查。

首頁既有 `/api/events` 缺少後端端點，屬 UI-01 範圍，本次未新增。
